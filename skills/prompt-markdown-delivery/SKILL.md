# 提示词 Markdown 协作交付

## 默认交付

- 用户已选择用 Markdown 文件在右侧阅读、选中文字并添加到对话进行批注。写提示词时实际创建 `.md` 文件，并在回复中提供可点击的绝对路径链接。
- 用户没有另行指定格式时，不再额外生成 TXT，也不在聊天里重复整篇长提示词。回复简短说明完成内容并链接主文件；用户明确要求在聊天里贴全文时照做。
- 新任务使用当前工作区的用户输出目录，文件名简洁且稳定，例如 `outputs/营地枪战_提示词.md`。不硬编码其他聊天的工作区路径。
- **严禁读取无关历史文件（节省上下文）**：撰写或修改提示词时，只读取触发的专项 Skill、用户本轮上传/指定的素材，以及与当前镜头直接关联的目标主稿（仅在用户明确提及或需定位同名/对应生成脚本时按名直读）。严禁为了“参考既有排版样式、开头句式或命名习惯”去全盘扫描工作区目录，或翻阅 `outputs/` 等目录下其他无关场次的历史 `.md` 提示词与脚本。
- Markdown 主文件包含当前完整、可独立提交的提示词。用自然段和必要的小标题方便阅读、定位及选区；通常不把全文包在代码围栏里。
- 修改说明、版本记录、待确认事项不混入提交给生成模型的提示词正文。

## 批注与后续修改

- 用户已打开或明确引用一个主文件时，先读取该文件和本轮批注，以用户最新编辑后的内容为基准，更新同一个主文件；不为每轮常规修改另造新主文件。
- 接收到选区、文件行号或评论时，定位对应原文，只修改授权范围，并处理由该修改造成的直接冲突；保留用户其他修改及当前素材绑定。
- 若需要保留修改前内容用于对照，放入工作区中间文件目录，不把临时备份作为新主稿交付。
- 使用右侧原生“显示更改”功能时，以实际界面及工作区支持为准，不声称仅凭 `.md` 格式就有修订记录、可点击复选框或逐项接受/拒绝功能。
- 默认在回复中简短列出主要修改；用户要求单独标注时，再生成独立的 Markdown 修改对照或待确认清单。清单记录确认状态，只有收到用户确认才标记已确认；不把待确认清单自动变成普通编辑的审批流程。
- 若环境提供打开文件到侧栏的合适工具，可使用它；否则提供文件链接让用户打开，不声称已经打开了右侧界面。

## 与提示词专项技能配合

- 继续应用对应模型、角色和场景的专项技能。本技能只规定交付与批注流程，不替代提示词内容规则。
- 专项技能中“在聊天代码块交付全文”的一般默认值，按用户已明确选择的 Markdown 文件方式执行。保留素材占位符、台词、音效等模型专用符号及用户已确认的内容。
- 当前请求明确要求其他格式、只给一段替换文字或仅回答问题时，按当前请求处理，不强制生成文件。
