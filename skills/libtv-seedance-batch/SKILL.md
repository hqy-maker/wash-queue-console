# LibTV Seedance 批量洗视频与上画布流程

将“多镜头本地原片分析 → 云端深度动作捕捉 → Seedance 2.5 样片生成 → 出片自检 → 1080P 转正片”固化为可复用、可多人并行的标准流水线。

配合 [seedance-video-recreation](../seedance-video-recreation/SKILL.md)、[seedance-video-prompts](../seedance-video-prompts/SKILL.md)、[libtv-cli](../libtv-cli/SKILL.md) 与 [prompt-markdown-delivery](../prompt-markdown-delivery/SKILL.md) 协同使用（若涉及特定项目角色设定集，可叠加对应角色一致性手册连戏检查）。

## 一、核心分工与默认规范

1. **人/Agent 看原片，Seedance 吃景深片（严禁把原片直接喂给 Seedance）**
   - **Agent 读取原视频**：直接多模态查看原片画面与音轨，还原精细表演、眼神、动作节拍、运镜轨迹与台词。
   - **声音核实不默认跑本地 Whisper**：直接听原片音轨核实对白、语气与 SFX；遇到声音极轻、杂音覆盖或拿捏不准的句子，**严禁靠口型或剧本脑补**，直接标明具体时间点与疑难点询问用户确认后再定稿。
   - **深度动作捕捉（默认 Plan A）**：原视频上传到 LibTV 画布后，在画布上点击「深度动作捕捉」产出 `depth_anything.mp4` 景深节点；`Seedance 2.5（样片模式）` 节点左侧**只连接构图/影调参考图 + 角色参考图 + 景深视频节点（按此 `1..N` 顺排）**，绝不把原片节点直接连进 Seedance。这样既保住本机算力，也对齐云端景深参考结构。

2. **默认模型与生成参数（除非用户本轮另有指定）**
   - **模型**：`Seedance 2.5（样片模式）`（`modelKey: star-video2.5-draft`）
   - **模式**：`modeType=mixed2video`（全能参考）
   - **画幅**：`ratio=21:9`
   - **清晰度**：`resolution=480p`（样片模式固定）
   - **时长**：`duration` 取**原片实际时长最接近的整数秒**（合法范围 `4–30` 秒；若原片 `< 3.5s` 或 `> 30.4s`，在预检阶段提前提示用户裁切或取舍）
   - **音频**：`enableSound=on`（默认保留同期对白与 SFX，无音乐除非用户要求）

3. **先铺节点不代点生成，先 Pilot 后放量，出片后自检**
   - **默认不代点 Seedance 生成（强制停顿点）**：完成素材上传、云端「深度动作捕捉」并把 `Seedance 2.5（样片模式）` 节点连好上游线、填好参数与提示词后，**默认不传 `--run`**，直接发画布链接给用户，**由用户在画布审阅确认后亲自点击「生成」**（除非用户明确说“这次直接帮我点生成 / 加 `--run`”）。
   - **先 Pilot 后放量**：新批任务先拿 **1~2 个镜头**走通上传、景深与样片节点配置，确认画布排版与提示词无误再批量铺开。
   - **出片自检再转正片**：用户在画布点击生成出 480P 样片后，按约定拉回样片对照原片/参考图做一轮出片自检并汇报结论；需修改则更新节点参数后继续留待用户手点生成，确认 OK 后再用命令一键转 1080P 正片。

4. **构图/影调参考图「最小必要局部涂白」（保住人物光影，拿不准就问）**
   - **何时处理**：将「构图/影调参考图」逐人与「角色图」比对；若构图图中的人物五官、发型/帽饰、帽带、局部配饰或无关人物与角色图不一致，先用 [whiteout_mask.py](./scripts/whiteout_mask.py) 在本地把**确实不对的局部**涂成纯白 `#FFFFFF`，让 Seedance 自行按角色图补全；**提示词里绝不提及涂白，按正常构图参考写入即可**。
   - **严禁整人遮死（核心光影规则）**：只涂确实不一致的**最小必要部位**，外扩边距克制收紧（默认 `pad_px=2`）。能只涂面部就尽量保留帽子/头发的受光高光；需连帽子一起涂白时，也必须**完整露出衣领、肩膀、衣服褶皱的受光面、侧逆光边与明暗投影**，让 Seedance 看见人物身上的光线方向而不跑偏。
   - **不确定涂哪直接问**：若遇到拿捏不准是否该涂（例如帽子要不要保光影、衣领/配饰是否留着、远景某人是否要涂）的部位，**直接带原图说明询问用户确认后再动手**，不要擅自扩大遮罩。
   - **涂白后必做视觉自检**：先用 `whiteout_mask.py grid`（小人物加 `--crop` 放大）精确定位顶点，再用 `apply` 输出无损 `.png` 后**必须多模态复看成图**，确认既没漏掉碎发/帽带残影、也没误吞关键衣领光影，并通过 `preflight_check.py` 后再上传画布。

## 二、四阶段执行流程

### 阶段 0：询问目标画布、接通盘点与本地预检

1. **先问清楚画布再动手（强制）**
   - 每次开始任务、**在执行任何上传或建画布操作之前**，必须先检查 `libtv status` 与 `libtv account info`；若 CLI 返回 `401 / 用户未授权`，启动 `libtv login web` 获取 `http://127.0.0.1:<port>/callback` 登录页后，优先通过 `chrome-devtools` MCP 在用户已登录的 Chrome 中打开回调完成无感续期并关闭该临时标签页（不挤掉浏览器登录态；若无 MCP 或浏览器也未登录再引导用户手动登录）。随后用 `libtv project list -s 10` / `libtv workspace list` 拉出近期画布清单，**明确向用户确认**：
     - 这次是**写入哪张现有画布**，还是**新建一张画布**（以及建在哪个项目/工作区下、叫什么名字）？
   - **未收到用户明确答复前，严禁擅自新建画布或往现有画布写入任何节点。**
   - 用户选定后，执行 `libtv project use <画布UUID>` 绑定当前工作目录，并立即将画布链接发给用户：`https://www.liblib.tv/canvas?projectId=<画布UUID>`。
   - **从左往右用画布（布局基准）**：若用户指定写入**已有画布**，先用 `libtv project <UUID>` 查出已有所有节点的右边界 `max_right = max(x + width)`，本轮新增节点/分组全部从 `max_right + 间距` 起**向右延展**，绝不压盖原有内容；单镜组内与多镜头之间也一律保持**从左往右**推进。
2. **整理镜头映射与去重共用资产**
   - 明确每个镜头对应的：`原视频`、`构图/影调参考图`、`角色参考图`（以及镜头命名/序号，如 `S01`、`S02`）。
   - 多镜头共用的角色定妆图、三视图或通用场景图，统一先上传到画布的「公共资产」分组并记录 `nodeKey`，跨镜直接按 `nodeKey` 连线复用，避免画布重复上传与重名冲突。
3. **运行本地预检**
   - 在 macOS 上统一用 `uv run --no-project python` 运行本 skill 自带的 [preflight_check.py](./scripts/preflight_check.py)（避免调 `/usr/bin/python3` 触发 Xcode 协议卡住），核实：
     - 所有参考图满足 Seedance 预检硬门槛：格式为 `jpeg/png/webp/bmp/tiff/gif/heic`、宽高均在 `300–6000px`、宽高比在 `0.4–2.5`、体积 `<30MB`；
     - 每个原视频的时长是否落在 `4–30` 秒并计算对应整数秒 `duration`；
     - 如有不合格素材，先报告用户更换/裁切，不带着报错硬跑。

### 阶段 1：多 Agent 并行「洗原片」与质检

- **并行调度选择**：
  - **轻量并发（默认，省配额）**：多个互不依赖的镜头用并行子 Agent / Workflow 分片洗词，每镜独立分析原视频并写出提示词与参数清单。
  - **`swarm` 协同模式（高要求、复杂对白或多人连戏镜头）**：开 2~4 个洗视频 Worker 分片分析原片，配 1 名专职 Verifier 在共享留言板上核对动作/运镜完整度、台词依据、连戏规范与参考素材对应关系，打回合格后再进下一阶段。
- **单个镜头交付物（双落盘）**：
  1. **本地 Markdown 备份**：按 `prompt-markdown-delivery` 规范保存可供用户选区批注的提示词文档。
  2. **画布建节点配置（结构化记录）**：目标 `duration`、节点前缀、各参考素材用途说明、以及预留景深节点占位符的提示词草稿（正文不留多余废话，按“先、随后、接着、与此同时、最后”组织节拍，台词用 `{台词原文}`）。
- **遇到拿捏不准的台词**：立刻记录镜头编号与时间点，汇总向用户确认，**不把未核实台词提交去生成**。

### 阶段 2：统一排布上画布 + 深度动作捕捉 + 自动连线

> **防冲突铁律**：并发只用于本地分析与写词；**所有 `libtv upload` / `libtv group` / `libtv node` 写画布操作由协调者按固定顺序与坐标统一执行**，避免多 Agent 并发改写 `.libtv/project.json` 或造成节点坐标叠压。

详细 CLI 写法、坐标模板与防重名约定见 [references/cli-and-canvas.md](./references/cli-and-canvas.md)。核心动作如下：

1. **按镜头建组并从左往右上传原片与参考图（若有涂白则传涂白图）**
   - 若该镜构图图经对比存在人物/细节差异并已完成本地「最小必要局部涂白」与视觉自检，`S01-构图图` **直接上传涂白后的 `.png` 成图**（涂白后仍需过 `preflight_check.py`）。
   - 每个镜头建独立普通分组（如 `S01`、`S02`），组内所有节点统一加镜头前缀（`S01-原片`、`S01-构图图`、`S01-角色图`、`S01-样片`）确保整张画布展示名全局唯一。
   - 严格遵守**从左往右**习惯：跨镜头从左向右顺排（或在现有画布最右侧 `max_right` 之后继续向右延展）；单镜组内也按「参考素材 → 原片 → 深度动作捕捉 → Seedance 样片 → 1080P 正片」从左往右横向流式排布。
2. **在画布上执行「深度动作捕捉」（优先接管用户现有 Chrome，不挤掉登录态）**
   - **优先使用 `chrome-devtools` MCP（`--autoConnect`）**直接操作用户已登录 Chrome 中的画布标签页（严禁擅用隔离浏览器重登导致用户网页端掉线）；若调试连接未开，停下来请用户在 Chrome 打开 `chrome://inspect/#remote-debugging` 勾选开关后再继续（仅在无 MCP 环境且用户确认时才退回 `browser` 子 Agent）。
   - **两步点击缺一不可**：选中对应 `S01-原片` 节点 → 点击顶部工具栏「深度动作捕捉」（此时仅创建出挂好原片的 `深度动作捕捉-*` 节点、默认 `720 P`，**尚未开始计算**）→ **必须再点击新节点工具栏里的「确认提取」**才会真正进入生成队列。
   - **等终态与归组**：待画布渲染出分辨率与时长（如 `2522 × 1080` / `0:07`）且 `libtv project <UUID>` 中该原片出边相连的 `isDepthMapRefOutput` 景深节点达到 `status == 2`（`loading == false`）后，记录其精确 `nodeKey`，并执行 `libtv group "<分组>" --node <景深nodeKey>` 将其纳入本镜分组（自动对齐并扩框）。
3. **CLI 自动连线并建 `Seedance 2.5（样片模式）` 节点（素材 `1..N` 严格对位，默认不加 `--run`）**
   - **素材序号与提示词顺序对齐铁律**：`libtv` CLI 在建节点 / 改参时会根据上游边类型固定把**图片排在前（`1..K`）、视频排在后（`K+1`）**写入 `mixedListOrder`（无论 `--left` 参数先后）。因此 `--left` 连线、提示词首句 `{{Node ...}}` 绑定与 Markdown 节点清单**一律严格按「构图图（`图片1`）→ 角色图（`图片2..K`）→ 景深视频（`视频K+1`）」从 `1` 到 `N` 顺排**，严禁把景深节点写在首句最前造成 `视频N` 错位排在 `图片1` 前面。
   - 在景深节点右侧（`x = 景深.x + 景深.width + ~200`，`y` 与顶行对齐）用 `libtv node --x <x> --y <y> create "S01-样片" -t video -g "<组>"` 新建节点（**`--x/--y` 写在 `create` 前**），仅连入「构图图 + 角色图 + 景深视频」（严禁连入原片节点）。
   - 写入参数：`-s "model=Seedance 2.5（样片模式）" -s modeType=mixed2video -s ratio=21:9 -s resolution=480p -s duration=<整数秒> -s enableSound=on`，**不要带 `--run`**（多行中文提示词通过 `uv run --no-project python` 的列表传参传入，避免 shell 转义失误）。
   - **刷新页面并视觉核验**：CLI 修改不会自动推送到已打开的浏览器标签页，需通过 `chrome-devtools` 刷新画布并点击展开 `S01-样片` 面板，截图核对顶部缩略图 `1..N` 与正文 `@图片1..@视频N` 标签、参数及待点击生成状态无误后，再发画布链接交由用户审阅点击「生成」（仅当用户明确指示“帮我直接跑”时才追加 `--run`）。

### 阶段 3：用户出片后的 480P 自检、调优与 1080P 转正片

自检检查项与汇报格式见 [references/self-check-template.md](./references/self-check-template.md)。

1. **用户点生成出片后拉片自检**
   - 当用户在画布点击生成且 480P 样片出片后（用户通知或确认状态完成时），通过 `libtv download -n <样片节点> --watermark false -o ./work/drafts` 将生成的 480P 样片拉回本地（非会员账号改传 `--watermark true`），直接多模态读取该样片并对照原片与参考图核对：
     - 人物长相/服装/道具是否符合角色图与构图图；
     - 表演动作、眼神视线、运镜路径与节奏是否贴合原片/景深片；
     - 台词咬字、停顿、音效与音画同步是否正常；
     - 有无多余人物、双胞胎脸、乱码字幕、水印/Logo 或明显崩坏。
2. **通知用户并等待决策**
   - 向用户发：**画布链接 + 逐镜自检结果（通过项 / 疑似瑕疵）**。
   - **若需修改**：按用户反馈修改提示词或参考图后，只对对应样片节点更新 `--prompt` / `--left`（同样**默认不加 `--run`**），通知用户在画布复核后亲自点击生成；若用户明确指示直接代跑，再加 `--run`。
   - **若确认 OK**：按用户指令在 **7 天有效期内**执行 `libtv video final -n <样片节点>`，原参数一键转出 **1080P 正片**；批量收片时用 `libtv download -n <分组或节点> --watermark false` 拉回本地。

## 三、常见阻塞与兜底规则

- **Seedance 真人合规拦截**：若参考图含真人且报合规不通过，提醒用户先在 LibTV 网页「角色库」录入该真人资产后再重跑；已通过审核的资产 60 天内免重审。
- **样片超过 7 天转正片限制**：`libtv video final` 仅支持 7 天内的样片；超时需对原样片节点重新 `--run` 生成新样片后再转。
- **单镜运行失败或超时**：先用 `libtv node <节点>` 查看失败原因，只重跑失败镜头，不重跑已成功的分组节点。
